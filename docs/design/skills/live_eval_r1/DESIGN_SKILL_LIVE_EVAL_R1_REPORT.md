# RocketForge Design Skill Live Eval R1 — Report

Live qualification of the project-local design skill stack installed in
Design Skill Foundation R1. **Not** the CAD/CAE Workbench redesign itself —
this run answers only whether the installed skills actually change agent
behaviour in the intended direction, live, under realistic and adversarial
tasks. No production UI, physics, or QML was modified.

Companion documents: `DESIGN_SKILL_LIVE_EVAL_R1_METHOD.md` (how),
`_RESULTS.md` (the numbers), `_FAILURES.md` (what was found and fixed),
`_RECOMMENDATIONS.md`, `_FILES.md`, `_CHECKPOINT.md`.

## Method

Two genuinely independent conditions per eval, generated by fresh
subagents with no access to this session's history (so CONTROL is an
honest naive baseline, uncontaminated by having authored the skills):

- **CONTROL**: a capable generic designer/engineer, explicitly forbidden
  from reading `.claude/skills/` or calling the Skill tool.
- **ROUTED**: a subagent instructed to invoke, live, via the Skill tool,
  the specific skills the ownership hierarchy assigns to that task — and
  to name which skills it invoked, so the claim is checkable.

Both conditions were reasoning-only (no file writes beyond their own output,
no implementation), per the program's hard rule.

**Blind scoring:** an independent third subagent reviewed both outputs
labeled Candidate A / Candidate B, with the label order alternated per eval
and the control/routed identity withheld, scoring against a pre-registered
rubric and this eval's specific pass/fail criteria.

**Independent reviewer:** the program's designated reviewer role
(`design-review`) is built for screenshots/URLs/HTML, which this run
produces none of (the hard rule forbids implementation). Rather than force
a bad fit, that role was filled by the dedicated blind-scoring subagent
described above — documented as an honest adaptation in
`DESIGN_SKILL_LIVE_EVAL_R1_METHOD.md`, not presented as literally running
`design-review`'s own rubric.

## Eval 2 — Fluid Properties

Control: weaker card-grid tendency, no default-chart ban stated. Routed:

## Eval 3 — Trade Study axes

Physics solves proposed: **zero, in both conditions.** Pareto semantics:
both correctly state the 2D plot is a projection of a front defined by all
objectives. Both PASS; routed edges ahead on RocketForge-specific

## Eval 4 — Nozzle realism

Fake physics proposed: **control proposed an exit-plane "plume cue"
glow** — a blocking failure. Routed proposed rendering/annotation upgrades
only, explicitly deferring any bell-contour feature. Honesty boundary:
routed states it; control's own honesty section contradicts its own
proposal two paragraphs earlier. 4.67 vs 2.33 (control blocking-failed).
Confirmed no regression after the unrelated eval-07 skill fix.

## Eval 5 — QML animation

Object ownership: both stable. Memory behavior: both bounded, neither
proposes per-solve object creation or `gc.collect()`-as-architecture.
Scientific logic in QML: neither. Both PASS; routed edges ahead. 5.00 vs
4.33.

## Eval 6 — Technical visual language

**A genuine skill deficiency was found here and fixed.** Pre-fix: routed
was strong on hierarchy/typography (5/5 each) but scored 1/5 on
accessibility — silent on contrast/WCAG entirely, while the naive control
flagged it unprompted (4/5). `rf-engineering-workbench` was edited to add
an explicit accessibility-reflex rule whenever it touches typography,
colour, or chrome. Post-fix: routed sweeps 5/5/5. Confirmed to generalize
to an unseen prompt (Thermochemistry warning state).

## Eval 7 — Engine Design 3D

**The more serious of the two deficiencies — this is a blocking eval.**
Pre-fix: **both** conditions blocking-failed. Control over-claimed
chamber/nozzle sizing to justify a "revolved solid" render. Routed —
despite genuinely invoking `rf-propulsion-visual-grammar` and
`rf-qtquick3d-viewport` and doing real codebase research — misclassified
`injector` as having "real solver code" because the name appeared inside
another module's own disclaimer about what is *not* built.
`rf-propulsion-visual-grammar` was edited to require verifying an actual
implementing module for each component, and to treat a name found only
inside a "not implemented" disclaimer as negative evidence. Post-fix: an
independent reviewer re-derived ground truth directly from the source
(not trusting either candidate) and confirmed routed now scores 5/5 on
both scientific honesty and fictional-capability avoidance, with **3D role:
explicitly declined** in favor of an honest 2.5D schematic extension
labelled "SYSTEM SCHEMATIC — IMPLEMENTED COMPONENTS ONLY." Confirmed no
regression on the adjacent eval (04) owned by the same skill.

## Eval 8 — stale snapshot

Mismatch detected: **YES**, by both conditions. Diagnosis: both correctly
identify the header-vs-schematic binding defect and correctly prescribe
rebinding the header to the same result snapshot as the schematic (not
auto-recalculating, not hiding the input). Both PASS; control edges ahead
narrowly on richness of remedy detail. Honest caveat recorded: the fixture
named the mismatch explicitly in the prompt, so this measures whether the
pattern is catchable once stated, not whether it surfaces unprompted from
a raw screenshot — flagged as a recommendation for a stronger future test.

## Eval 9 — chart/table grammar

Both avoid the universal 50/50 template failure and reason per-workspace.
Routed more precisely separates Thermochemistry's chart-free Calculator
from its chart-dominant-when-active Sweep tab. 4.50 vs 4.00.

## Eval 10 — 1366x768

A genuine tie (4.50 each), strong in complementary ways — recorded
honestly rather than forced to a winner.

Eval 11 ("Should RocketForge replace its central visualization with Qt

## Independent-review findings

reviewer's word, before it drives a skill change.
